# Deal and Property database schema

RET-003 implements the first PostgreSQL schema with SQLAlchemy and Alembic. The tables contain only the fields already defined by the Rethos handoff.

## `deals`

| Column | Type | Constraints / behavior |
|---|---|---|
| `id` | UUID | Primary key; generated by API |
| `name` | text | Required; API enforces existing 1–160 character input constraint |
| `status` | text | Required; defaults to `draft` |
| `created_at` | timestamptz | Required; database current timestamp |
| `updated_at` | timestamptz | Required; database current timestamp; ORM updates it on row changes |

## `properties`

| Column | Type | Constraints / behavior |
|---|---|---|
| `id` | UUID | Primary key; generated by API |
| `deal_id` | UUID | Required FK to `deals.id`, unique (one property per deal) |
| `address` | text | Nullable |
| `city` | text | Nullable |
| `asset_type` | text | Nullable |
| `area_value` | numeric | Nullable; positive when present |
| `area_unit` | text | Nullable; required together with `area_value` |
| `created_at` | timestamptz | Required; database current timestamp |
| `updated_at` | timestamptz | Required; database current timestamp; ORM updates it on row changes |

The database enforces the existing area-value/area-unit pair and positive-area rules. The primary keys and unique `properties.deal_id` constraint provide the only indexes; no additional indexes were justified for this initial dataset and query set.

## Migration and rollback

Migration `apps/api/migrations/versions/20260930_0001_deals_properties.py` creates both tables. `alembic upgrade head` applies it; `alembic downgrade base` rolls it back by dropping `properties` and `deals` (and their data). Run downgrade only when intentionally removing this schema. Alembic records applied revisions in `alembic_version`.

## Local fixture

`python -m app.seed` inserts one idempotent, clearly synthetic Deal/Property fixture after migrations are applied. It contains no market data or external-source claims.
